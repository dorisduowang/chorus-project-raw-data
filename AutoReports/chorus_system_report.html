1. Executive Summary

CHORUS is a sophisticated multi-agent knowledge management and retrieval system designed for the Knowledge Lab at the University of Chicago. The system combines intent-driven query routing, hybrid retrieval-augmented generation (RAG), structured registry lookups, and conversation memory to provide intelligent responses about lab members, research projects, computing resources, and documents.

9. Further Improvements & Roadmap

This section outlines planned enhancements and potential features for future versions of CHORUS. Items are categorized by priority and estimated complexity.

9.1 Short-Term Improvements (High Priority)

LLM-Based Query Classification

Replace regex-based classification with LLM classification for improved accuracy. Current regex patterns (75+) are brittle and require manual maintenance. An LLM classifier would better handle edge cases and ambiguous queries.

  • Estimated improvement: 15-20% better intent detection
  • Trade-off: +200-300ms latency per query
  • Implementation: Fine-tune Haiku with classification examples

Semantic Registry Index

Add embedding-based search for registry data (people, datasets, projects). Currently, registry lookup uses exact/fuzzy string matching. Semantic search would enable queries like "researchers working on similar topics to X".

  • Embed all registry entities with descriptions
  • Enable similarity-based discovery
  • Support "find similar" queries across entity types

Response Streaming

Implement streaming responses for both CLI and Slack interfaces to improve perceived latency. Users would see responses appear incrementally rather than waiting 5-7 seconds for complete output.

9.2 Medium-Term Enhancements

Hypergraph-Based Relevance Boosting

Use the existing hypergraph (1,312 nodes, 594 edges) to boost search relevance. When a query mentions an entity, boost results from connected entities.

  • Query "James Evans" → boost collaborators, co-authored papers
  • Query "APTO project" → boost team members, related datasets
  • Leverage co-authorship and topic similarity edges

Proactive Recommendations

Based on conversation context, proactively suggest relevant resources, people, or datasets the user might not have asked about but could be useful.

  • "You might also want to talk to [person] about this"
  • "Related dataset available: [dataset]"
  • "Similar project: [project]"

Multi-Turn Planning Agent

Add a planning specialist that can break down complex research questions into sub-queries, execute them in sequence, and synthesize results.

  • Handle: "Help me find collaborators for an NLP project"
  • Execute: topic search → people search → availability check
  • Return: synthesized recommendation with reasoning

Automated Registry Updates

Implement automated weekly sync with external data sources to keep registry information current without manual intervention.

  • OpenAlex API sync for publication metrics
  • Midway directory crawler for resource updates
  • Google Scholar scraping for citation updates

9.3 Long-Term Vision

Interactive Hypergraph Visualization

Build a web-based D3.js visualization of the research hypergraph, allowing users to explore relationships between people, projects, and publications visually.

Voice Interface

Add speech-to-text and text-to-speech capabilities for hands-free interaction in lab settings.

Cross-Lab Federation

Enable CHORUS instances at different labs to share anonymized query patterns and collaborate on improving responses.

Research Paper Integration

Directly index and chunk lab publications for full-text search with direct quotes from papers.

9.6 Known Limitations

Current Limitations:
  1. Single-Threaded RAG Server: Python http.server not optimized for high concurrency
  2. Sparse Hypergraph: Only 594 edges; missing discussion/mentorship relationships
  3. Static Registry Data: Manual updates required; publication metrics become stale
  4. Limited Multi-Language: Entity extraction optimized for English only
  5. No Offline Mode: Requires active API connections; no graceful degradation

10. Conclusion

CHORUS v2.0 represents a mature, production-ready knowledge management system with sophisticated multi-agent orchestration, hybrid search, and conversation memory. The system successfully serves the Knowledge Lab community with sub-7-second response times and high accuracy on factual queries.

The roadmap outlined in Section 9 prioritizes improvements that will enhance user experience (streaming, proactive recommendations), improve accuracy (LLM classification, semantic registry), and enable new capabilities (hypergraph visualization, multi-turn planning). With continued development, CHORUS can evolve into a comprehensive research intelligence platform.

Key Achievements (v2.0):
  • Web search integration with Anthropic built-in tool
  • Enhanced conversation memory with entity tracking
  • 5.5x memory compression for long conversations
  • Sub-millisecond entity extraction overhead
  • 92% accuracy on tool routing (RAG vs web search)
